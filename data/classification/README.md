# Coded regimes: file layout

Coded under the frozen [regime coding rule](../../docs/regime_coding_rule.md). No price index was examined while coding.

## `regime_measures.csv` (one row per measure, hand-coded)

| Column | Meaning |
|---|---|
| country | Country name as in the tracker |
| product | `electricity` or `gas` (household) |
| code | 1 freeze or cap below cost; 2 quantity-based cap; 3 lagged formula cap; 4 tax or levy cut; 5 transfers only |
| measure | Short name |
| start_month, end_month | `YYYY-MM`, by the 15th-of-the-month rule; end blank if still in force |
| step_ups | Dated increases in a controlled price, `YYYY-MM:+x%` separated by `;` (test 2 events) |
| coverage_share | Share of household customers covered (0 to 1); blank if all |
| coverage_note | Source and year of the coverage share |
| source_url, source_ref | Source and the article, section or page that supports the code |
| evidence | `primary` (legal text, regulator decision, government or regulator release) or `secondary` |
| read_date | Date the source was read |
| verified | `yes` once the code rests on a primary source |
| notes | Anything a reader needs to check the code |

## `regime_baseline.csv` (one row per country and product)

The regime without any crisis measure: `3` if a regulated tariff passes costs through a published formula with a lag of at least one month, otherwise `6`; `regulated_2021_07` is 1 if household prices were set or approved by a regulator or government in July 2021.

## `regimes.csv` (generated by `code/02_expand_regimes.py`)

Country, product and month from 2019-01, with the main code by precedence (1 before 2 before 3 before 4 before 5 before 6), every code in force as flags, the low-coverage and unverified flags, and the measures in force.

## `tracker_measures_*.csv` (generated by `code/01_extract_policy_trackers.py`)

The Bruegel trackers as a checklist. `candidate = 1` marks household price measures touching electricity or gas; every candidate must end up either coded or noted as not applicable. These extracts are rebuilt locally from the downloaded tracker files and are not committed, because Bruegel's licence (CC BY-ND 4.0) does not allow altered copies to be redistributed (coding rule, Amendment 4).

## `tracker_reconciliation.csv` (generated by `code/04_reconcile_tracker.py`)

One row per tracker candidate (128 in the 2021 to 2023 tracker, 12 in the 2026 tracker), identified by tracker file, row number and country, with its disposition: `coded` (the `regime_measures.csv` rows that carry it, as `country|product|code|start_month`), `not_coded` (the reason: motor or heating fuels, district or collective heating, network charges, wholesale interventions, firms only, targeted transfers, or non-price programmes) or `to_code` (a household measure not yet coded). The script stops if a candidate is unassigned or a cited row does not exist. Status on 11 November 2026: 81 coded, 59 not coded, none left to code.

## `coding_log.csv` (written by `code/03_update_codes.py`)

Every change made to the coded files after the first draft: date, row key, column, old value, new value. Batches of checked changes are applied with `py -3 code/03_update_codes.py updates.json`.

## Special flags

`special_flags` in `regime_measures.csv` (carried to `regimes.csv`) marks codes that tests report with and without: `formula_driven` (a levy cut produced by the levy's own formula), `endogenous_trigger` (a rate that switches with the wholesale price or the CPI) and `opt_in` (an optional regulated offer; its take-up share is entered as coverage). See Amendment 2 of the coding rule.

## Classification questions decided on 11 November 2026

The primary-source checks left eight questions the coding rule did not settle. They were decided in Amendment 2 of the [coding rule](../../docs/regime_coding_rule.md) and applied as follows:

1. Belgium: code 4 ends 2023-03; from April 2023 the 6% VAT is permanent and offset by excise.
2. Ireland PSO levy: code 4 from 2022-10 with the flag `formula_driven`.
3. Czechia VAT waiver: code 4 kept for 2021-11 and 2021-12; CZSO recorded it in the HICP as a 0% VAT rate in those months.
4. Estonia universal service: code 1 from 2022-10 to 2024-06 with the flag `opt_in`; take-up 13% of consumers in 2023 (Competition Authority), so it also carries the low-coverage flag.
5. Spain: electricity VAT (2021-07 to 2024-12) and the 2026 cuts coded as they applied, with the flag `endogenous_trigger`.
6. Latvia gas: code 3 from 2019-01 to 2023-04 (six-monthly pass-through of the gas price in the captive-customer tariff; SPRK ended the regulated tariff on 30 April 2023).
7. Croatia electricity: code 1 from 2022-04, when the government package limited HEP's household tariff increase to 15% (9.6% on the average bill); code 6 before.
8. Greece gas: baseline 0 kept; RAE reports the gas retail market fully liberalised since 1 January 2018.

Rows still resting on secondary sources are marked `verified = no` and listed in `regime_measures.csv`; tests are run with and without them (coding rule, section 5).

## Freeze (12 November 2026)

The coded files were frozen on 12 November 2026, before any price outcome series was downloaded for estimation (coding rule, section 7). `freeze_manifest.csv` records the SHA-256 of `regime_measures.csv`, `regime_baseline.csv`, `regimes.csv`, `not_coded_measures.csv` and `tracker_reconciliation.csv`; `py -3 code/05_freeze_regimes.py check` stops if any of them has changed. Estimation scripts run this check first. Any later change is made as a dated amendment to the coding rule, with the manifest rewritten in its own commit, and results are reported under both the frozen and the amended coding.

Amendment 4 (17 November 2026) removed the Bruegel measure names from `tracker_reconciliation.csv`; the manifest was rewritten in a separate commit to record its new checksum, and the other four files are unchanged.

State at the freeze: 116 coded measures (89 on primary sources, 27 flagged `verified = no`), 54 country-product baselines, and a panel of 5,076 country-product-months from 2019-01 to 2026-10. All 140 tracker candidates are coded or carry a reason for not being coded.
